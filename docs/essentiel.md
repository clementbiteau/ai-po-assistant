### [What : ce que fait l'assistant](what-how-why.md#1-what--ce-que-fait-lassistant)

- Le PO reçoit trop de retours, par trop de canaux, pour tout lire et tout comparer.
- L'assistant les analyse, classe les besoins et rédige les user stories.
- Cinq onglets, dans l'ordre du travail : Inbox, Analyse, Priorisation, User stories, Export.
- Les neuf fonctionnalités attendues par la consigne sont couvertes.
- Le PO garde la décision : il corrige une note, tout se recalcule.

### [How : comment ça marche](what-how-why.md#2-how--comment-ça-marche)

- Trois rôles d'IA : l'analyste, le stratège, et les rédacteurs en parallèle.
- Le code enchaîne les étapes : un workflow voulu, prévisible et testable.
- Des réponses au format imposé, validées, corrigées une fois si besoin.
- Chaque citation est vérifiée mot pour mot dans la source.
- Un run : environ 110 s et 0,16 €, 14 citations exactes sur 14.

### [Why : pourquoi l'IA ici, et pas là](what-how-why.md#3-why--pourquoi-lia-ici-et-pas-là)

- L'IA pour le jugement sur du texte libre.
- Le code pour le calcul, le format exact et les décisions à auditer.
- RICE chiffre, MoSCoW tranche, les contraintes non négociables passent devant.
- Sonnet 5 choisi par la mesure, face à Haiku et aux modèles plus puissants.
- Limite assumée : pas encore de suivi des tendances dans le temps.

### [Au-delà de la consigne](au-dela-de-la-consigne.md)

- Tout ce qui dépasse la consigne est signalé en pâle dans l'application.
- Pour le PO : tri de l'Inbox, preuves vérifiées, exports Jira, progression en direct.
- Pour une app en ligne et sûre : connexion sur invitation, droits dans la base, budgets.
- Pour piloter : console Admin (coûts, comparaison des runs, journal des agents).
- Pour la suite : une feuille de route des connecteurs en trois phases.
